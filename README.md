# Moïse 다음 여행지

**https://soyellll.github.io/trip-vote/**

친구들끼리 다음 여행지와 여행 시기를 정하는 모바일 웹앱.

1. 이름을 적고 **2027년 캘린더에서 가능한 날짜**를 고릅니다 (탭 = 하루, 꾹 눌러 드래그 = 여러 날)
2. 가고 싶은 나라를 검색해 추가합니다 — 지도에 위치가 찍히고, **인천 출발 비행시간·권역·왕복 항공권 대략치**가 붙습니다
3. **한 명당 2표**로 익명 투표. 과반이 나오면 바로 확정, 아니면 상위 3곳을 두고 결선(재투표 또는 돌림판)
4. 결과 화면에 **모두 겹치는 날짜**가 히트맵으로 나옵니다

코멘트는 본인 말투로 쓰고 **번역기 말투로 바꾼 뒤에만** 제출됩니다. 변환은 브라우저에서 규칙 기반으로
돌아가서 서버도 API 키도 필요 없고, **원문은 기기 밖으로 나가지 않습니다.**

- 정적 페이지 (GitHub Pages)
- 실시간 동기화 + 저장 (Supabase)
- 지도 데이터 · 여행지 정보는 레포에 포함 (외부 API 없음)

설정 전에도 그냥 열면 **한 기기에서 폰을 돌려가며 쓰는 모드**로 동작합니다.

## 설정

### 1. 프로젝트 + 스키마

Supabase 새 프로젝트를 만든 뒤 **SQL Editor** 에 `supabase/schema.sql` 을 붙여넣고 실행합니다.
그다음 `supabase/migrations/` 의 마이그레이션을 적용합니다.

```bash
npx supabase@latest login
npx supabase@latest link --project-ref <프로젝트 ref>
npx supabase@latest db push
```

프로젝트 ref 는 대시보드 주소의 `/project/<ref>` 부분이고, 로그인 후
`npx supabase@latest projects list` 로도 확인할 수 있습니다.

### 2. 익명 로그인 켜기

**Authentication → Sign In / Providers → Anonymous sign-ins** 를 켭니다.
이걸 안 켜면 앱이 단말 모드로 떨어집니다.

### 3. 접속 정보 넣기

**Project Settings → API** 에서 URL 과 anon key 를 복사해 `config.js` 에 넣습니다.

```js
window.TRIP_VOTE_CONFIG = {
  SUPABASE_URL: "https://xxxx.supabase.co",
  SUPABASE_ANON_KEY: "eyJhbGciOi..."
};
```

이 두 값은 **공개되어도 되는 값**입니다. anon key 는 브라우저에서 쓰라고 만든 키이고,
실제 권한은 `schema.sql` 의 RLS 정책이 정합니다. 커밋해도 됩니다.

### 4. 배포

`main` 에 push 하면 `.github/workflows/pages.yml` 이 자동 배포합니다.

## 여행지 정보

`data/places.js` 에 75개 나라가 들어 있고, **전부 인천(ICN) 출발 기준**입니다.

| 필드 | 뜻 |
|---|---|
| `h` | 비행시간. 직항이 있으면 직항, 없으면 일반적인 경유 포함 소요시간 |
| `d` | 직항 여부 |
| `p` | 왕복 항공권 대략 범위 (만원). 성수기·비수기 차이가 커서 넓게 잡았습니다 |
| `r` | 권역 (동아시아 / 동남아시아 / 유럽 / 오세아니아 …) |

실시간 조회가 아니라 **고정된 참고값**입니다. 화면에도 "대략치"로 표시합니다.
검색에 없는 곳은 "직접 추가"로 넣을 수 있고, 그 경우 지도와 정보는 붙지 않습니다.

값을 고치거나 나라를 추가하려면 `data/places.js` 에 한 줄 넣으면 됩니다.

## 지도

`data/world.js` — Natural Earth 110m 를 좌표 소수 1자리(약 11km)로 줄이고
아주 작은 섬을 걷어낸 175개국 폴리곤입니다 (127KB). 등장방형 도법으로 그리고,
남극은 잘라내 모바일 비율에 맞췄습니다. 외부 지도 API 를 쓰지 않습니다.

작아서 폴리곤이 없는 곳(홍콩·싱가포르·몰디브·괌·사이판·팔라우)은 나라가 칠해지지 않고
점과 항로만 찍힙니다.

## 말투 변환

`lib.js` 의 `TV.tone.translatorize`. 문법 교정기가 아니라 **말투 지문 지우기**입니다.

- 이모지, `ㅋㅋ`/`ㅠㅠ` 자음 표기, 반복 부호, 물결 제거
- 은어·줄임말 사전 치환 (존맛 / 개꿀 / 갬성 / 강추 / 가성비 …)
- 종결어미를 `~습니다` 격식체로 정규화. 문장부호 없이 이어 쓴 글은 ㅁ체 경계에서 끊습니다
- 1인칭을 저/제가로, 구어 부사를 표준어로

결정적(deterministic)이라 누가 써도 같은 문체로 수렴합니다. 그게 익명성에 도움이 됩니다.
사전에 없는 개인 특유의 단어는 그대로 남으니, 자주 새는 단어가 있으면 `LEXICON` 에 추가하세요.

## 익명성을 위해 일부러 한 것들

- **`ballots` 에 타임스탬프가 없습니다.** 시각이 남으면 투표 순서와 대조해
  "세 번째로 투표한 사람이 어디에 표를 줬는지"가 그대로 드러납니다. `id` 도 `gen_random_uuid()` 라
  시간순 정보가 없습니다.
- **표는 Realtime 으로 흘려보내지 않습니다.** publication 에서 `ballots` 를 뺐습니다.
  실시간으로 나가면 개발자도구를 켜 둔 사람이 "표 INSERT" 와 "누가 방금 투표 완료로 바뀌었는지"를
  나란히 보고 짝지을 수 있습니다. 표는 결과를 열 때 한 번에 가져옵니다.
- **한 표에 담긴 여러 코멘트의 순서를 섞어서 저장합니다.**
- **코멘트 원문은 서버로 아예 가지 않습니다.** 변환이 브라우저에서 끝나고, 변환문만 저장됩니다.
- 화면에 뜨는 코멘트는 가나다순으로 정렬해 보여줍니다.

날짜는 반대로 **이름과 함께** 저장됩니다. 누가 언제 되는지는 서로 알아야 일정을 잡을 수 있으니까요.

## 알려진 트레이드오프

**읽기는 방 코드로 막지 않았습니다.** Supabase Realtime 구독은 REST 헤더를 전달하지 않아서,
읽기까지 방 코드로 막으면 실시간 동기화가 통째로 죽습니다. 그래서:

- **쓰기**는 `x-room-code` 헤더로 방을 증명해야 합니다 — 남이 내 방을 망칠 수 없습니다.
- **읽기**는 이 프로젝트에 세션이 있는 사람이면 다른 방 데이터도 조회할 수 있습니다.

친구들끼리 쓰는 용도로는 충분하지만, 민감한 내용을 담을 앱은 아닙니다.
꼭 막아야 한다면 Supabase 의 Custom Access Token Hook 으로 방 코드를 JWT 클레임에 넣고
RLS 를 `auth.jwt() ->> 'room'` 기준으로 다시 쓰면 됩니다.

```
supabase/functions/tone/       (미사용) 예전 AI 변환 프록시. 나중에 AI 를 붙이고 싶을 때 참고용

```
